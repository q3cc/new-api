# 多种体验金

在系统设置 → 计费与支付 → 体验金中启用功能，添加体验金种类并设置名称、分组及允许发放。保存后自动分配稳定 ID。例如，Ds 体验金绑定 Ds 分组，Gpt 体验金绑定 Gpt 分组。

在用户管理的发放体验金操作中选择种类，设置金额与有效期。金额可以每次不同，用户可以同时持有多个种类。钱包按种类显示可用余额、分组及各笔有效期。

邀请奖励启用“邀请奖励发放体验金”后，选择已保存且允许发放的奖励种类。奖励金额沿用额度设置中的邀请人奖励金额，奖励有效天数在体验金设置中填写，0 表示永不过期。关闭此选项沿用原来的余额奖励。

每种体验金仅限对应分组使用，不会扣除其他分组的体验金。相同分组内按先到期先扣除，退款退回原发放记录。不同种类也可以对应同一个分组，其余额仍按种类分别展示。

体验金用尽后，超出部分与普通余额一样全额扣款，可以扣成负余额。欠费低于免除门槛时不再扣款也不记为负余额，默认门槛为当前展示货币的 0.5，可在体验金设置中调整（留空用默认值，填 0 表示始终全额扣款）。门槛在该次请求预留体验金时冻结，之后调整设置或切换展示货币都不影响进行中的请求。体验金支出不计入钱包已用额度，请求次数仍然累计。

停止某种类发放后，已经领取的体验金可继续使用。已发放种类的分组不能修改；调整用途时新增种类并停止旧种类发放。已有种类保留 ID，不能删除或重新分配给其他种类。

## API 兼容

Root 配置 GET/PUT `/api/trial-credit/config` 新增 `types` 数组（`id`、`name`、`group`、`enabled`）、`affiliate_type_id` 及 `waive_threshold`（欠费免除门槛，按当前展示货币计价，缺省为 0.5）。创建种类提交 `id: 0`，服务端返回分配后的 ID；修改请求必须保留已存在种类。`enabled` 是功能总开关，`affiliate` 选择体验金邀请奖励，`affiliate_days` 设置其有效天数。

管理员可 GET `/api/trial-credit/types` 获取可发放种类。POST `/api/user/:id/trial-credit` 新增 `type_id`，其余金额、有效期和幂等发放编号保持不变。只有一种类时兼容省略 `type_id` 的旧请求。服务端决定分组，客户端不提供分组。

GET `/api/user/self/trial-credit` 新增 `balances`，按种类返回 `type_id`、`name`、`group`、`balance`；保留总余额和原分页结构。各发放记录新增 `type_id`、`type_name`、`group`；支付请求记录保留使用分组。

## 升级

启动迁移为发放表新增种类与分组字段，并将原单分组配置转换为默认种类。旧发放绑定原分组，额度、剩余额度、有效期、发放来源与操作者保留。支付请求记录新增免除门槛字段；升级前已预留的请求该字段为 0，按全额扣款处理。迁移可重复执行。
